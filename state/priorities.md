# Priorities

How the owner ranks the projects. Marshal uses this to choose between two due items and to
decide which sessions to pause first when the weekly budget runs tight. Fill it in with a
short interview: ask the owner these four questions, in the decision format, and record the
answers here with the date.

1. Which project is closest to money or a hard deadline?
2. Which is important but never urgent (so it gets some time every day)?
3. Which can wait when budget is tight?
4. Anything that must never be paused?

## Ranking (EXAMPLE, replace)

1. **ProjectA** (closest to revenue). Repos: project-a-api, project-a-web.
   - First: the launch checklist.
2. **ProjectB** (important, not urgent). Repo: project-b.
3. **ProjectC** (side project). Repo: project-c.

## Budget rule (EXAMPLE, replace)

When the weekly budget runs tight, Marshal pauses the lowest-ranked sessions first and keeps
the top two projects running. It does not ask each time. Project B is never paused for a whole
day: at least one ProjectB session gets work every day.

## Overrides (dated)

- (none) Example: "2026-01-02: today's allowance is raised from 43% to 60% because I am away from the computer."
